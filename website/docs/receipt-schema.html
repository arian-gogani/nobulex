Receipt Schema

Every action enforced by Nobulex produces a signed receipt. The receipt is the proof artifact. It contains everything needed for independent verification without access to the originating system.

Full Receipt Fields

FieldTypeDescription
receipt_idstringUnique identifier for this receipt
indexnumberPosition in the hash chain (sequential)
timestampISO 8601When enforcement was evaluated
agent_didstringW3C DID of the agent that performed the action

Action Object

The action field contains the full payload of what the agent attempted. This is what hanselhansel asked about: tool inputs are included, not just tool names.

FieldTypeDescription
action.toolstringName of the tool or action invoked
action.argumentsobjectFull arguments passed to the tool (query, amount, patient_id, etc.)
action.resultstring"executed" if allowed, "blocked" if denied

Example: "called search_tool with query='cancel order 8821' and got back confirmation #4419" is captured in the action object, hashed into the outcome_hash, and signed.

Enforcement Object

FieldTypeDescription
enforcement.decisionstring"ALLOW" or "DENY"
enforcement.matched_rulestringThe specific covenant rule that was evaluated
enforcement.evaluated_atISO 8601When the rule was evaluated

Covenant in Effect

The receipt carries the covenant that was active at the time of enforcement. This means you can answer two questions from a single artifact: "what was the agent allowed to do" and "what did it actually do."

Hash Chain Fields

FieldTypeDescription
outcome_hashhex stringSHA-256 hash of the full action payload (tool, arguments, result, timestamp)
previous_hashhex stringChain hash from the previous receipt (or zeros for the first)
chain_hashhex stringSHA-256 of previous_hash + outcome_hash. Links this receipt to the chain.
signaturestringEd25519 signature over the entire receipt. Verifiable with the agent's public key.
verifiablebooleanAlways true. Indicates the receipt can be verified independently.

Verification

Any third party can verify a receipt by:

1. Recomputing outcome_hash from the action payload
2. Checking chain_hash == SHA-256(previous_hash + outcome_hash)
3. Verifying the Ed25519 signature against the agent's public key
4. Walking the chain to verify integrity from receipt #1 to #N

No access to the originating system is required. The receipt is self-contained.
